PickMyUni — University Comparison Platform

A tool that lets students compare Australian university courses on what they actually decide by — fees, duration, entry requirements and institution. I designed the database behind it and built the layer that pulls live course data from university APIs into one consistent schema.

Overview

Choosing a university course in Australia means opening a dozen tabs. Every institution publishes course data in its own structure, with its own naming for fees, intakes and entry requirements, and none of it is comparable side by side.

PickMyUni is Stepping Stone's answer to that. My part is the data layer — the schema, the API integrations, and making sure data from different sources can sit in one table and still mean the same thing.

The questions

  • What do students actually compare on? The schema had to be built around the comparison, not around any one university's data format.
  • How do you reconcile inconsistent sources? RMIT and Deakin publish course data differently; both had to map to one canonical shape.
  • How does search stay fast? Filtering across institutions, disciplines and fee ranges needed query and index design.
  • How do you keep it current? Course data changes every intake, so the pipeline had to refresh rather than re-import.

The data

Data arrives from live university APIs and internal course records: institution, course, discipline, fees, duration, campus, intake dates and entry requirements.

Each provider's payload passes through a transformation layer that maps its field names and fee structures onto one canonical course model before anything reaches a student-facing page.

How I built it

  • Designed a normalised MySQL schema for universities, courses, fees, intakes and entry requirements, so adding an institution is a mapping exercise rather than a restructure.
  • Integrated the RMIT and Deakin APIs, handling pagination, rate limits and partial responses.
  • Standardised and validated on ingest — missing fees, malformed dates and duplicate course codes are quarantined before they reach the front end.
  • Wrote the search queries and indexes supporting course search, filtering and side-by-side comparison across institutions.

What it shows

01

Schema design is the product

Getting the course model right up front meant new institutions could be added by writing a mapping, not by rebuilding the database.

02

Source data is messier than its documentation

Real API responses included missing fees, inconsistent intake formats and duplicate course codes — validation on ingest turned out to be non-negotiable.

03

Students filter on fewer fields than expected

Fee range, discipline and location dominate search behaviour, which pointed directly at which columns needed indexing.

04

Standardisation unlocks the comparison

Once every source mapped to one shape, side-by-side comparison and fee ranking became ordinary queries rather than special cases.

Outcome

PickMyUni runs on a single MySQL schema fed by live university APIs, with search, filtering and comparison working consistently across institutions.

The same underlying data also feeds the analysis I do on student course-selection behaviour — which is how a comparison tool doubles as a source of insight into what students are actually looking for.
