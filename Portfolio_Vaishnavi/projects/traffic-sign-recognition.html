Traffic Sign Recognition & Obstacle Detection

A convolutional neural network trained on roughly 50,000 images to classify 43 traffic-sign categories at 95% test accuracy — then extended past classification into real-time obstacle detection on live video with OpenCV.

Overview

Traffic-sign recognition is deceptively hard. Signs are photographed at different distances, angles and light levels; several classes look nearly identical at low resolution; and the class distribution is heavily imbalanced.

I built this to work through a full computer-vision pipeline myself — preprocessing, architecture, augmentation, evaluation — and then the step most projects skip: taking a trained classifier and making it run on live video.

The questions

  • Can a CNN separate 43 similar classes reliably? Speed-limit signs differ by a single digit at low resolution.
  • How much does augmentation actually help? The goal was to measure the generalisation gain, not assume it.
  • Where does the model fail? Which classes get confused matters more than one headline accuracy number.
  • Does it hold up outside the dataset? Static test accuracy and live-video performance are not the same thing.

The data

Roughly 50,000 labelled traffic-sign images across 43 categories, captured in varied lighting and weather conditions.

All images were resized and normalised to a consistent input shape, then split into training, validation and test sets with stratification so class balance was preserved — and the test set was held back from training and tuning entirely.

How I built it

  • Designed the network in Python — stacked convolution and pooling layers for feature extraction, dropout for regularisation, and a dense softmax head over the 43 classes.
  • Applied augmentation — rotation, scaling and brightness adjustment — to simulate real camera conditions and reduce overfitting.
  • Tracked training against validation throughout, so overfitting showed up early rather than at the end.
  • Extended it to live video with OpenCV for real-time frame processing and bounding-box annotation.

What it shows

01

95% accuracy across 43 classes

Strong performance on the held-out test set, given how visually similar several of the sign categories are.

02

Augmentation closed the generalisation gap

Rotation, scaling and brightness adjustment measurably reduced overfitting and lifted validation performance over the un-augmented baseline.

03

Errors cluster, they don't scatter

The confusion matrix showed misclassifications concentrated among visually similar signs — particularly speed-limit variants — pointing at where more data would pay off.

04

Live video is a different problem

Moving from stills to real-time frames introduced motion blur, scale variation and frame-rate constraints that static accuracy simply doesn't capture.

Outcome

A working computer-vision pipeline: a CNN classifying 43 traffic-sign types at 95% test accuracy, wrapped in an OpenCV layer that processes live video and annotates detected objects in real time.

The wider lesson was about evaluation. A single accuracy figure hides the interesting part — the confusion matrix and the gap between static and live performance are what tell you whether a model is usable.
