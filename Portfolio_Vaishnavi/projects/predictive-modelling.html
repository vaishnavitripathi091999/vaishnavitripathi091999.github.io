Overview

Most machine-learning write-ups stop at the leaderboard: a model, a score, a conclusion. That's the least useful part for a business.

The work that matters sits either side of it — getting real, messy data into a modellable state, and translating a trained model into something a stakeholder can act on. These workflows deliberately cover the whole path, not just the modelling step.

The questions

  • What does the data actually support? Exploratory analysis first, to establish which relationships are real.
  • Which model family fits? Regression and classification compared on their merits, not on familiarity.
  • Is the performance genuine or leaked? Careful splitting and cross-validation, so the score reflects unseen data.
  • What does it mean for a decision? Feature importance and error analysis translated into plain language.

The data

Each workflow starts from raw, real-world data — missing values, inconsistent types and outliers included — with the handling strategy decided per feature rather than applied blindly across the board.

Every transformation is fitted inside the training fold rather than on the full dataset, so no information from the test set leaks backwards into preprocessing and inflates the result.

How I built it

  • Cleaned and explored with pandas — distributions, correlations and class balance mapped before any model was fitted.
  • Engineered features — encoding categoricals, scaling numerics and deriving new variables where domain logic justified them.
  • Trained and tuned multiple models in scikit-learn with hyperparameter search and cross-validation rather than one train/test split.
  • Chose metrics to match the problem — R² for regression, F1 for classification — based on the cost of each error type, not on convention.

What it shows

01

Feature engineering beat model choice

Thoughtful feature construction moved performance more than swapping one algorithm for another — the return on understanding the data was consistently higher.

02

The right metric changes the answer

Accuracy flattered models on imbalanced data; F1 exposed the precision/recall trade-off and changed which model was actually preferable.

03

Cross-validation exposed fragile models

Models that scored well on a single split showed high variance across folds — a reminder that one number is never enough.

04

Interpretability earned the buy-in

Feature-importance analysis was what made the output trusted. A model nobody understands doesn't get used, however good the score.

Outcome

A repeatable modelling workflow rather than a one-off notebook: structured preparation, reproducible feature pipelines, honest cross-validated evaluation and a written interpretation layer that connects the model back to the decision it supports.

That structure is what I bring to analytics work — the value isn't in the algorithm, it's in being able to defend every step between the raw data and the recommendation.
